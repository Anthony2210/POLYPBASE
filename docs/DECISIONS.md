# Product and technical decisions

Each entry records a decision and its scope. It does not prove deployment or authorize changes to production. Dates refer to the recorded decision or the milestone that provides evidence for it.

| Date or milestone | Decision | Scope and reference |
|---|---|---|
| Project invariant | Zero is a measurement, never missing data. Django decides permissions and transitions for the active institution; preserve authors, lineage, and audit records. | [AGENTS.md](../AGENTS.md) |
| October 14, 2026 status | One canonical reading per box and ISO week. A conflicting POST does not correct the existing reading; correction is explicit and audited. | [Measurements](reference/measurements-temperatures-probes.md) |
| October 14, 2026 status | Week-only target: Monday is the ISO key, the day is unknown; do not invent a day. If an intervening subculture makes ordering ambiguous, ask for the actual day or cancel; no override. | Target, not current storage: [imports](reference/imports-exports-transfers.md) |

| October 14, 2026 status | Administration is desktop-only. Retire alerts and the large shared catalog; preserve the previous alert records. | [Frontend](reference/frontend.md) · [Architecture](reference/architecture.md) |

AI-written EN and JA are shown in the app at once and marked "ai" for review: JA by the Japanese reviewer, EN by the English reviewer; FR is reviewed in the PR without a status. Never overwrite validated text silently. Keep the same review spreadsheet; automatic synchronization is planned but not built. | [Terminology and i18n](reference/terminology-i18n.md) |

A label shows the species then the recorded strain name, separated by a single space, with no separator character. A strain name too long for the label blocks printing instead of being cut. | [Frontend](reference/frontend.md) |
| November 25–27, 2026 | Box search will offer an Active / Inactive / All filter next to the search field, applied before results are cut; a per-device default in user preferences comes later. Not built yet. | [Frontend](reference/frontend.md) |
| November 25–27, 2026 | Weekly record tracking: the Overview works in ISO weeks (Monday to Sunday). Each box may have a planned weekday (default: none) that only admins can change, shown on the box page. A transplant child takes the parent's day by default (checkbox, checked by default). Being built; not available in the app. | [Measurements](reference/measurements-temperatures-probes.md) |
| November 25–27, 2026 | An anomaly is a box with no record on its planned day, not caught up yet, visible from the day after the planned day. A record on another day of the same ISO week counts as on time; anomalies never concern values. A box without a planned day is never an anomaly. Anomalies stay visible for the current and the previous ISO week; older ones only on the box page. | [Measurements](reference/measurements-temperatures-probes.md) |
| November 25–27, 2026 | Overview counters: "To record" (boxes planned today, not recorded this week), "Done" (recorded this week), and "Anomalies"; the "soon" filter is removed. | [Frontend](reference/frontend.md) |
| November 25–27, 2026 | A technician may enter a missing record for any past free week; it is marked as entered after the fact in history and audit. The status is computed by the server (Django is authoritative). | [Measurements](reference/measurements-temperatures-probes.md) |
